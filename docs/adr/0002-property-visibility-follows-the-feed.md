# Property visibility follows the Feed Listing, not an editorial publish

A Property goes live on its Site as soon as the Sync creates it, and is Withdrawn (hidden but never deleted) when its Feed Listing is deactivated or disappears. Properties therefore have no Draft/Published lifecycle. Editorial Content edits go live on save, and only Pages, Guides and Curated Lists have drafts. We chose this so that a bookable listing is never missing from the site while it waits for copy, and so that the Sync can write facts into a single document version.

## Considered Options

- **Hidden until an Editor publishes.** Rejected in favour of time-to-market for new listings.
- **Drafts on Property.** Rejected. Every Sync would need to patch both the published version and any pending draft, which is a common source of lost edits.

## Consequences

- Withdrawn keeps the Editorial Content and the slug, so a returning listing comes back as it was. A Withdrawn Property's URL responds 410, or redirects to its Location.
- The slug is Editorial Content. It's set once from the listing name and never regenerated by the Sync. The legacy plugin regenerated slugs on every sync, which broke URLs whenever a unit was renamed.
- The site must render sensibly for a Property with empty Editorial Content by falling back to feed-provided text.
